Resource providers

A resource provider is one kind of outside system an organization uses: a package registry, a source control host, a DNS host. It offers several resource types. Jive makes sure each resource exists, using credentials the organization connected once.

Decided (Alex, 2026-11-04): “there’s probably a resource provider and multiple types of resources that said resource provides … Like a source control host provides repos, orgs, maybe teams? A package repository probably provides both packages and orgs.” This is the model Terraform’s providers and Crossplane’s managed resources use; what Jive adds is that its server holds the credentials, and callers hold only a session.

Three layers

Section titled “Three layers”
Layer Package Defines
Abstract jive-abstract-resource-provider What every provider exposes: connect, refresh, key sync
Provider kind jive-abstract-resource-provider-package-registry The resource types a package registry offers (org, package) and the arguments each takes
Implementation jive-resource-provider-package-registry-npm Does it on npm: a Convex component and frontend code

Each organization configures exactly one implementation per provider kind. Built for the one kind that exists (schema.ts).

Provider kinds and their resource types

Section titled “Provider kinds and their resource types”
Provider kind Resource types Implementations Status
package-registry package; org npm package built (as the connector below); org proposed
source-control-host org, repo, team GitHub Proposed. Replaces the proposed code-repository connector, which offered repos only.
dns zone, record Cloudflare Proposed

A resource can belong to another: a package to an org, a repo to an org.

What an implementation exposes

Decided (Alex, 2026-11-04): “a package which implements a resource provider needs to have both frontend code and a convex component”.

The Convex component

Section titled “The Convex component”

@jive-sh/server installs it and calls it. Proposed contract, one Convex module per concern:

  • Decided (Alex, 2026-11-04): connect takes “the actual credential blob, expiration, and whether it’s refreshable”, and refreshing is a separate call.
  • Decided (Alex, 2026-11-01): “Connectors must expose an API which allows for key rotation”. The draft is keys.syncPublicKeys (jive_key_rotation_api.md).
  • A component stores no credentials: the server passes one on every call. Built that way today.
  • EnsureResult is today’s EnsureInstanceResult: ready, inProgress, personNeeded or refused (instance.ts).
  • The build checks the component’s generated ComponentApi type against the abstract’s contract type for exact equality. Built (abstract.ts).

The frontend code

Section titled “The frontend code”

Runs in the Jive browser extension and walks a person through the outside system’s own screens to produce the credential. See Connecting an account.

What exists today

Section titled “What exists today”

Built, under the names used before “provider”:

Today Becomes
jive-abstract-resource stays
jive-abstract-resource-connector: no contract of its own jive-abstract-resource-provider
jive-abstract-resource-connector-package-registry jive-abstract-resource-provider-package-registry
jive-resource-connector-package-registry-npm jive-resource-provider-package-registry-npm

Today’s package-registry contract has one resource type, a package, implied rather than named: resource.ensureInstance with { packageName }. It also has five lower-level calls: packageExists, createPlaceholder, and list, register and remove trusted publishers (contract.ts). There’s no connect, refresh or key sync call yet.
